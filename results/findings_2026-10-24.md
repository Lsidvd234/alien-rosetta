## Claim 2 (coverage), causal: remove one multiplication fact from training

`--drop-pair P,Q` removes every training multiplication whose operands need the single-digit product PxQ
(about 9% of multiplications for 5,6 and 3,4). Test at trained sizes, meaning start:

| Removed | Problems that need it | Problems that avoid it |
|---|---|---|
| 5 x 6 | **0.05** | 0.92 |
| 3 x 4 | **0.10** | 0.96 |
| 2 x 2 | pending | pending |

The model does not infer a missing multiplication fact from the rest: it gets right only the pieces it saw. This turns
"generalisation stops at coverage" into cause and effect, and it is the experiment Faith and Fate could not run on
closed models.

## Scratchpad: the model learns a fixed-length template, not the loop (2026-10-25)

`maths-meaning-scratch`: every multiplication target is the long-hand working (one "digit x digit + carry = value"
step per digit, rows, partial products, sum, answer), trained at the usual sizes (mul up to 2x2).

| Test | No scratchpad (`maths-meaning`) | Scratchpad |
|---|---|---|
| mul up to 2x2 (trained) | 0.957 | **1.000** |
| mul 3x1 | 0.653 | **0.137** |
| mul 3x2 | 0.130 | **0.000** |
| mul 3x3 | 0.027 | 0.000 |

Decoded outputs show why: for 3-digit numbers the model writes **exactly 2 steps per row**, the most it ever saw in
training, so it silently skips a digit, while every step it does write is correct arithmetic. Example (base 7):
`464 x 3`, gold `4x3+0=15 6x3+1=25 4x3+2=20 =2055`, model `6x3+0=24 4x3+2=20 =204`. The scratchpad made the trained
sizes perfect and longer sizes worse: it learned the procedure as a fixed-length template, not as "one step per
digit". This is the Faith and Fate scratchpad finding in its clearest form.

**With 5x6 removed from training (`maths-meaning-scratch-drop56`), trained sizes:**

| | No scratchpad (`maths-meaning-drop56`) | Scratchpad |
|---|---|---|
| exact, problems that need 5x6 | 0.05 | **0.26** |
| exact, problems that avoid it | 0.92 | **1.00** |
| written 5x6 steps correct | - | **0.49** (173 of 353) |
| all other digit steps correct (avoid set) | - | **1.00** (857 of 857) |

The errors land exactly on the missing fact: every other step is perfect, and the 5x6 step is right only about half
the time. Writing the working helps somewhat (0.05 to 0.26 exact) but does not recover the missing piece. In the
needs-pair set the other steps fall to 0.87 only because a wrong 5x6 step passes a wrong carry on.

Scorer fix (train/maths.py, 2026-10-25): the step check compared steps by position, so these runs were labelled
"digit product" errors. It now reports a separate "wrong step count" error, checks each written step's arithmetic on
its own (`written_steps_arith_ok`, also split by dropped pair), and saves every prediction (`preds`). The running
`maths-meaning-scratch-drop56` uses the old scorer: its dropped-pair step comparison is still valid (trained sizes,
right step count), its longer-size step labels are not.
